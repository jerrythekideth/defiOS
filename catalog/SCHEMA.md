# Protocol card schema (`catalog/<protocol>/card.yaml`)

A card holds **public facts about one protocol**: which contracts exist, what
they are called, which exact calls make up each action, which parameters must be
pinned to the Avatar, what to read, and which UI routes to avoid.

A card never holds anything about a specific vault: no balances, positions,
nonces, credit-account addresses or permission status. Those live in the
operator's own repo (`books/<vault>/book.yaml`, generated by `defios sync`) and
in `defios.yaml` (`book_vars`).

Every card starts as `status: draft`, `reviewed: false`. Only a human reviewer
flips `reviewed` after checking each address against at least two independent
sources (protocol docs, verified source on a block explorer, defi-kit).

## Top level

| key | required | meaning |
|---|---|---|
| `protocol` | yes | id, same as the folder name |
| `name` | yes | display name |
| `chain_id` | yes | 1 for Ethereum mainnet |
| `status` | yes | `draft` → `reviewed` → `deprecated` |
| `reviewed` | yes | `false` until a human signs off |
| `sources` | no | where the facts come from (docs, explorer, defi-kit paths, payload files) |
| `defi_kit` | no | defi-kit permission bundle covering this protocol: `<defi-kit protocol key>/<action> [param=[v,…]] (note)`, e.g. `lido/deposit`, `morphoVaults/deposit targets=[…]`. Keys and parameter names are exactly defi-kit's (see `catalog/DEFI_KIT.md`); `scripts/defikit_map.py --check` and the tests verify them, and concrete values (addresses) must be in defi-kit's option list |
| `contracts` | yes | map of contract name → contract (see below) |
| `ui_routes_to_avoid` | no | list of `{ui, via, why}`: routes the official UI uses that the agent must not |
| `reads` | no | list of reads (see below) |
| `actions` | yes | map of action name → action (see below) |
| `dead_permissions` | no | functions that can never succeed for a vault (admin-only, operator-only) |
| `not_needed` | no | plain-language list of permissions people add but do not need |
| `notes` | no | free text; long-form risks go in `NOTES.md` next to the card |

## Contracts

```yaml
contracts:
  pool:
    address: "0xA9d17f6D3285208280a1Fd9B94479c62e0AABa64"  # checksummed
    kind: erc4626            # erc20 | erc4626 | erc721 | router | adapter | queue | facade | ...
    decimals: 18             # tokens: used by `defios plan` to turn "1.5" into raw units (checked over RPC when set)
    aliases: [gearbox pool, kpkwstETH]
    defi_kit: "gearbox/deposit targets=[0xA9d1…]"
  wstETH: { ref: lido.wstETH }          # reuse another card's contract
  vault:  { address: $book.vault }      # instance chosen per vault, set in defios.yaml book_vars
  silo:   { address: { read: "savETH.silo()" } }   # resolved at read time
  depositor: { address: TODO }          # unknown: never guess an address
```

`address: TODO` is allowed (with a comment saying what is missing). The engine
skips any action that needs an unresolved address and reports it.

## Reads

```yaml
reads:
  - id: pool_shares
    target: pool
    sig: "balanceOf(address account) returns (uint256)"
    args: [$AVATAR]
    decimals: 18          # optional, for display
```

`defios sync` runs reads with `eth_call` and writes the results into the book.

## Actions and calls

```yaml
actions:
  lend:
    summary: "wstETH -> kpkwstETH"
    calls:
      - target: wstETH
        sig: "approve(address spender, uint256 amount)"
        args: { spender: pool, amount: $amount }
      - target: pool
        sig: "deposit(uint256 assets, address receiver)"
        args: { assets: $amount, receiver: $AVATAR }
      - target: pool
        alt: true             # alternative to the previous call, not required
        sig: "depositWithReferral(uint256 assets, address receiver, uint256 referralCode)"
        args: { assets: $amount, receiver: $AVATAR, referralCode: 0 }
```

Call keys:

| key | meaning |
|---|---|
| `target` | contract name in this card, `card.contract`, or `$book.<var>` |
| `sig` | full Solidity signature **with parameter names**; tuples written inline: `f((address token, uint256 amt) order, uint32 x)` |
| `args` | map of param name → value spec (below). Omitted params get a neutral sample value in checks |
| `send` | `true` when the call sends ETH (needs the `Send` execution option) |
| `operation` | `call` (default) or `delegatecall` (needs the `DelegateCall` option; only CoW's order signer today) |
| `calls_params` | names of array-of-calls params (`(address,bytes)[]`, multicall `bytes[]`). The role must scope them element by element |
| `optional` | nice to have; a missing optional call does not make the action `missing` |
| `alt` | alternative route for the previous call |
| `free` | receiver-like params deliberately left free, each with a reason (rare; needs human OK) |
| `verified_sig` | `false` when the signature is not yet confirmed from verified source or a live permission |
| `note` | free text |

Action keys used by `defios plan` (all optional):

| key | meaning |
|---|---|
| `input` | contract (in this card, or `card.contract`) or `ETH` that `--amount` is denominated in; its `decimals` convert the human amount. `$amount` / `$shares` get the raw value; for `send:` calls the ETH value is the amount |
| `defaults` | plan-time values for free `$vars` (e.g. `referral: "0x0…0"`). Any other free `$var` must be given with `--param`: plan never fills one with a check sample |

`plan` emits each required call (approves included) or, if the role rejects
it, the first `alt` with the same free variables that the role allows;
`optional` calls are skipped; an action with a `sign:` / `external:` step cannot
be planned.

Non-call steps (signed orders, things a third party does) use `sign:` or
`external:` instead of `sig:`; the engine reports them but does not check them.

Arg value specs:

| spec | meaning | pinned? |
|---|---|---|
| `$AVATAR` | the vault (Safe) address | yes: role must enforce it |
| `pool`, `lido.wstETH` | a contract from a card | yes |
| `{ one_of: [weth.WETH, etherfi.weETH] }` | any of these | yes, to that set |
| `$book.credit_account` | per-vault value from `defios.yaml` `book_vars` (`gearbox_v3.credit_account`) | yes |
| `$amount`, `$shares`, `$token` | free variable chosen at plan time; in checks a sample, or `book_vars["<protocol>.<name>"]` when set | no |
| `0`, `"0x…"` literal | fixed value | literal addresses yes, numbers no |
| `{field: spec, …}` | tuple param, field by field | per field |
| `[spec, …]` | array param, element by element | per element |

**Rule:** every `receiver`, `recipient`, `owner`, `onBehalfOf`, `to`,
`beneficiary`, `controller` (and similar) parameter must be pinned to `$AVATAR`
(or listed under `free:` with a reason). The test suite enforces this.

## Dead permissions

```yaml
dead_permissions:
  - target: minting
    sig: "TODO"                 # or a full signature, or `selector: "0x…"`
    why: "mint is onlyRole(MINTER_ROLE): a vault can never call it"
```

`defios check` flags any live permission matching one of these as `known-dead`
so it can be removed.

## How `defios check` uses a card

For each call it builds real calldata (engine-encoded), evaluates it against the
decoded role, then builds hostile variants: every pinned parameter replaced by
`0x…dEaD`, and every `calls_params` array given one arbitrary call. A call is

* `allowed` when the intended call passes and every hostile variant fails,
* `unsafe` when the intended call passes and some hostile variant also passes,
* `missing` when the intended call fails.

With `RPC_URL` set and an Operator configured, the same calls are confirmed with
an `eth_call` of `execTransactionWithRole` from the Operator against the live
modifier.
